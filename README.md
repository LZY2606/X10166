# Lockfile 语义合并室（Semantic Lock Merge Room）

一个零外部依赖（仅 JDK 17 + JUnit 5 测试）的本地 Web 应用，用于对自定义 lockfile
做**语义级三方合并**，而不是脆弱的文本合并。

## 构建与运行

```bash
./gradlew classes                                   # 构建检查
./gradlew test                                      # 运行测试
./gradlew run --args='--host 127.0.0.1 --port 5238' # 启动
```

打开 http://127.0.0.1:5238 ，页面标题为「Lockfile 语义合并室」。
可选参数 `--data <目录>` 指定会话持久化目录（默认 `./data`）。

## 自定义锁定格式 `lockfile v1`（.lsl）

```
lockfile v1
root app@1.0.0
root tool@2.0.0 [os=linux | os=darwin]      # 根依赖：精确版本 + 可选平台条件

package app@1.0.0
  source registry:https://repo.example.com/app-1.0.0.tgz   # 来源坐标
  integrity sha256:<64 位小写十六进制>                      # 完整性摘要
  platform os=linux & arch=aarch64                          # 节点级可选平台
  child libx@1.0.0
  child opt@0.9.0 [!os=windows]
```

- 顶层声明**根依赖**；每个包节点含名称、版本、来源、完整性摘要、可选平台条件、子节点精确引用。
- 节点身份是 `name@version`，**同名不同版本可共存**。
- 同一**来源坐标 + 版本**的完整性摘要必须一致，否则报完整性冲突。
- 平台条件是布尔表达式（原子 `k=v`/标识符，运算符 `! & |` 与括号），
  比较时先规范化为**排序后的析取范式（DNF）**，因此 `a|b` 与 `b|a`、
  `a&(b|c)` 与 `(a&b)|(a&c)`、`!!a` 与 `a` 都被视为等价，绝不依赖原始字符串。
- 输出采用完全稳定的排序（根、包、子引用），同一语义图产生字节一致的文本，
  满足 parse → print → parse 等价且打印幂等。

## 合并语义

- **节点三方合并**：两侧一致取一致值；仅一侧相对 base 修改则快进；
  两侧分别修改产生 `NODE_MODIFY`；一侧删除、另一侧修改同 id 节点产生 `NODE_DELETE`。
- **引用三方合并**：按（父、子名、精确版本、规范化条件）做三方集合合并；
  两侧独立新增/分别改向同一子依赖时产生 `EDGE_DIVERGE`，可选 LEFT / RIGHT / BOTH / BASE。
- **删根 + 传递升级**：某分支删除根依赖、另一分支只升级其传递节点时，
  被升级节点因无根可达而被**可达性清理**，不会被当成冲突；输出解释删除了什么及原因。
- **完整性冲突**：同坐标同版本摘要不同产生 `INTEGRITY` 冲突，选择后重写所有共享节点。
- **裁决后重新验证**：人工选择删除某版本后，重算所有父引用与根可达性，
  自动清除指向被删节点的边并清理不可达子树，不留下悬空节点。
- **指纹绑定**：每条裁决绑定 base/left/right 三份原始文本的 SHA-256；
  任一输入变化后旧裁决标记为 stale 且不会自动应用。
- **悬空引用与诊断**：解析期与合并期检查引用目标是否存在、摘要格式、重复声明等。

## 页面能力

粘贴三份 lockfile；查看解析诊断、SVG 包图、来源/完整性表、可达清理说明；
逐项解决冲突（可撤销）；发布并下载稳定排序的合并结果（带版本号与指纹）。
乐观锁 `revision` 会拒绝并发的过期写入（HTTP 409）。

## 持久化

原始文本、解析诊断（每次实时计算）、裁决、发布版本均以 JSON 原子写入数据目录；
重启后未完成会话可在右上角下拉中继续。

## 测试覆盖（`src/test`）

同名多版本共存、摘要冲突、删根+传递升级、平台条件等价、悬空引用、
不可达清理、旧裁决失效、并发编辑冲突、parse-print-parse 等价，以及会话持久化恢复。
